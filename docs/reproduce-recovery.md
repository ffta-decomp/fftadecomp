# Reproduce one ASM-to-C recovery iteration

This public toolkit includes the actual local compiler/comparison/preflight,
CPU-case executor, extraction codecs and transactional task CLI. It does not
contain the private implementation checkout, ROM, original extracted code,
private fixtures or machine configuration. No undocumented private directory is
a prerequisite for the steps below. See [AGENTS.md](../AGENTS.md),
[claim rules](../CONTRIBUTING.md), [extraction](extract-asm.md) and the
[O2 source lookup](o2-reconstruction-quick-reference.md).

## 1. Prepare the pinned tools

```sh
git clone --recurse-submodules https://github.com/hitsmaxft/fftadecomp.git
cd fftadecomp
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r tools/requirements-extract.txt
python3 tools/bootstrap.py
```

Also install `clang`, GNU `make` and ARM binutils providing `arm-none-eabi-as`,
`ld`, `objcopy`, `objdump` and `nm`. Bootstrap checks the clean agbcc submodule
at `da598c1d918402c42c0c0d7128ba14567f3175e9`; it builds serially into
`build/toolchain/agbcc` and removes its successful intermediate tree. It does not
build a ROM. Reports capture the actual host preprocessor, compiler binary,
binutils and Python; pinning agbcc alone does not promise every host matches.

## 2. Select and unpack one complete native method

Choose an active-group function from [the catalogue](../data/functions.csv) and
request/confirm central ownership before implementation. Native ID and address
remain stable when you infer better C names. Check all original callers, returns,
shared frames/tails, physical field widths, alias/reload effects and history.
Module spans and unknown modes require qualification, not an assumed C ABI.

```sh
python3 tools/identify_rom.py "$RETAIL_ROM"
python3 tools/extract_asm.py --rom "$RETAIL_ROM" \
  --file "$ASM_FILE" --verify --output "$PRIVATE_OUTPUT/reference-method"
```

`ASM_FILE` is one of that entry's `asm_paths`. All game-derived output stays
private. Use explicit typed interfaces to existing helpers; do not replace an
unknown callee with an invented behavior stub. Complex low-level bodies remain
interface dependencies rather than a new recovery campaign.

## 3. Reconstruct and compile one C candidate

Put your original C draft plus the headers it actually needs under ignored
`build/work/`. Export the same symbol you pass as `METHOD_SYMBOL`; preserve the
observed register and stack arguments, width, CFG, definition and reload order.
The following prepares one local comparison manifest; it grants no task or gate:

```sh
python3 tools/prepare_public_method.py --native-id "$NATIVE_ID" \
  --symbol "$METHOD_SYMBOL" --source build/work/candidate.c \
  --asm-tree "$PRIVATE_OUTPUT/reference-method" --asm-file "$ASM_FILE"
python3 tools/build_function.py --retail "$RETAIL_ROM" \
  --config "build/public-methods/$NATIVE_ID/manifest.json" \
  --module "$METHOD_SYMBOL" \
  --candidate-module "build/public-methods/$NATIVE_ID/candidate-module.json" \
  --output-dir "$PRIVATE_OUTPUT/round00"
```

Use a new output directory for each changed round and reuse the prepared native
manifest. Candidate O2/interwork settings are fixed, not a flag search. The
reference symbol interface file is generated by the full ASM unpack when needed;
for a method-only extraction, generate that interface separately and copy only
its generated `asm/external_thumb_symbols.s` into ignored local `asm/` before a
candidate needing those helper aliases:

```sh
python3 tools/extract_asm.py --rom "$RETAIL_ROM" \
  --file asm/external_thumb_symbols.s --output "$PRIVATE_OUTPUT/interfaces"
mkdir -p asm
cp "$PRIVATE_OUTPUT/interfaces/asm/external_thumb_symbols.s" asm/
```

`config/symbols.ld` supplies published address bindings, not helper bodies or ABI
proof. Resolve missing bindings from source, preserve actual helper widths and
side effects, and keep new local bindings private until they are independently
established. The tool emits binary, ELF, symbols, disassembly, offset-by-offset
differences, toolchain/input hashes and stage timings. Strict preflight verifies
range/entry/provenance/ELF policy; a rejection is not a delivered function.

## 4. Diagnose, validate and record

Read the **first structural divergence** before changing source: operation/type,
CFG/shared return, definition lifetime/reload/allocation, then placement. Change
one supported cause. Follow the existing three-hypothesis and near-exact whole-
method diagnosis rules; preserve all failed costs and old budgets. Defined-value
fixed-register locals or documented empty constraints can express a concrete
allocation requirement, but never invent operands or hide a function in ASM.

Record rounds with [the workflow CLI](recovery-workflow-cli.md). Use one shared
SQLite ledger per collaborating installation, not copied databases. Each decision
keeps source/header/binary/toolchain pins, hypothesis, full elapsed time and next
action. Submit a reached per-function gate immediately. Independent complete
native identity is a mechanical gate; nonexact work needs the source-derived
branch/effect oracles, caller composition and negatives described by
[the local runner](local-module-migration.md). Install its explicit dependency:

```sh
python3 -m pip install -r tools/requirements-behavior.txt
python3 tools/run_module_cases.py --help
```

The public runner consumes a bank you derive independently from original source;
no private game bank is required to use it. CPU fixture success is bounded
behavior evidence, not natural gameplay or hardware proof.

## 5. Freeze, share and integrate

Give the confirmed claim issue permitted original work and hash/range summaries;
do not attach ROMs, extracted ASM/assets, private paths, claim tokens or logs.
An independent actor verifies actual full-range provenance. Integrate accepted
functions coherently and prove production-linked identity; do not rebuild the
whole ROM for every local trial. A full game integration requires the separate
implementation and recovered assets; this public toolkit does not distribute a
ready-to-build game or claim gameplay completion.

Record the naming closeout and successful/failed transfer lesson. Report newly
matched **original ASM bytes**, counting each native envelope once, separately
from generated C length, semantic/independent/integrated gates and mixed ASM.
Compare completed absolute clock hours, including failures and handoff gaps.
