# C recovery execution and throughput

The operating objectives are newly accepted C bytes/hour, newly exact-matched
whole-function original ASM bytes/hour and complete iteration latency. Select complete
gameplay methods within [core system priorities](game-recovery-priorities.md).
Keep ABI, independent behavior checks, revision/toolchain provenance and batch
integration gates intact. Source lines and test counts are supporting facts,
not delivery measures.

The active campaign uses [battle group map/reduce](battle-group-recovery.md).
Finish and deliver current claimed methods first. Subsequent autonomous claims
stay inside the shared battle group, start with small complete dependencies and
advance toward their consumers. Complex low-level dependencies receive reusable
typed interface contracts, not implementation migration. Other systems remain
deferred except for source-proven dependencies of this battle group.

Read [the pinned agbcc O2 generation guide](agbcc-o2-matching.md) for a new
source-shape cause. State the observed mechanism and predicted change; name an
RTL pass only when pass evidence establishes it. Equivalent C spelling alone
is not a supported matching hypothesis.

Use the [GBA reference index](gba-asm-to-c-resources.md) for targeted ISA,
interface, draft or matching-tool questions. Its general research workflow is
adapted to our existing fixed-profile, claim and acceptance rules; collecting or
installing the entire corpus is not a prerequisite for implementation.

Use the [upstream source-family study](pokeemerald-reconstruction-reference.md)
and [EDS discrepancy/RTL guide](eds-matching-reference.md) selectively. The user
permits documented fixed-register locals and instruction-free empty ASM
constraints for concrete matching requirements when readable logic and valid
operand definitions are preserved. These do not invalidate complete byte
identity. Explain the affected value/lifetime, retain the pinned normal compiler
and full-range gate, and record the constraint in the existing lesson. Empty
output-only ASM cannot create a valid input value. Emitted instructions still
use mixed accounting; this is not permission for opaque ASM bodies, arbitrary
compiler overrides, blind permutation searches or automatic old-budget resets.

## Ownership and concurrency

The workflow CLI owns atomic claims, rounds, gates and commit receipts. All
implementation actors autonomously select disjoint core methods; one active
method per actor, with exclusive source/header/output paths. The current local
execution protocol sets compiler capacity. Only shared production/Git needs one
writer. Preserve active claims and original clocks across recovery.

The administrator controls priorities and execution efficiency, not candidate C
review, acceptance or fixed method assignment. Empty ready queues trigger
source qualification and reuse of existing indexes/exclusions, not waiting for a
manager or repeated polling. A successful compiler family improves priority; it
is not an admission requirement for an established core source contract.
Continue eligible complete methods in a productive family; no forced group
rotation or fixed function-size filter. Do not split a frame or invent wrappers.

Retain the actual immutable manifest used for a local build and its hash. A
mutable shared path does not preserve the input after integration changes. An
existing capture or exact hash-matching Git blob can restore provenance without
compilation. If necessary, refresh only the method's native report with unchanged
source and prove identical output; never silently edit a frozen report. Producer
proof repair is distinct from independent verification.

Complete native whole-exact C uses independent mechanical provenance/full-range
verification, not duplicate human C review or unchanged behavior banks. Nonexact
semantic promotion still requires independent source/behavior acceptance. No
administrator acknowledgement blocks another actor's next method. Submit the
local gate immediately before optional documentation; `finish` is not a credit.

Details remain in current documents and ledger records. Short notifications only
request rereading. Log actual changed revisions, reuse unchanged instructions and
do not rerun a closed audit. Normal method/disposition boundaries do not end an
autonomous lane while eligible work remains. No global classification barrier,
static actor list or arbitrary ready-task quota substitutes for useful work.

## Choose a bounded core cohort

Reuse source-hash-bound inventories and current exclusions. Within core business
priorities, rank complete methods by applicable frozen source-shape lessons,
contract readiness and expected original bytes per full delivery effort. Names,
address proximity, size and caller ABI alone do not prove a compiler family.
Prepare one representative before expanding an uncalibrated source shape.

The claiming actor pins complete original boundaries/revision, source/manifest,
ABI and helpers, CFG/shared tails, data widths/order/alias effects, independent
acceptance obligations, local commands and stop conditions. Reuse established
family facts but verify site-specific differences. Do not require a new runtime
bank for a full-native exact proof; prepare independent oracles where nonexact
semantic delivery requires them.

## Preserve compiler structure from the first implementation

Apply the [source-writing guide](asm-to-c-migration.md#write-c-from-the-observed-structure)
before editing a matching candidate. Record which instruction or CFG difference
the chosen C expression should explain; a formulation is not a reusable rule
until its generated output and relevant independent checks support it.

Use observed-role names and readable C while preserving proven control-flow and
memory effects. Keep repeated arms, variable lifetimes and shared tails explicit
until a transformation has evidence. Do not merge work for stylistic reasons and
then repeatedly undo it to recover the original compiler structure.

Use the [naming closeout](c-recovery-naming.md) to improve function and variable
names while preserving indexed identities, linkage and compiler structure.
Include its measured cost in the original method clock; do not turn it into a
second rewrite or a full-ROM verification cycle.

Classify each access as ordinary owned RAM, callback/alias-visible state, or
MMIO/asynchronously observable state before choosing qualifiers. An unknown field
name is not a reason to make every access volatile. Record required snapshots and
reloads across calls explicitly. Preserve signed load types, local-object
lifetimes and values held stable after a callback; equivalent algebra alone does
not preserve the original compiler structure. Remove a qualifier only with a
source-backed access/effect contract and relevant independent checks.

Use one fixed O2 candidate build configuration. Do not switch optimization
levels, enumerate flag combinations or build a configuration matrix. Diagnose
source types, control flow, memory accesses, lifetime and layout with that same
configuration. Historical accepted artifacts retain their recorded provenance;
this policy does not trigger a rebuild of unchanged milestones.

Diagnose differences in this order:

1. ABI, interworking, prologue/stack and return paths.
2. CFG, dispatch, shared tails and read/call ordering.
3. Instruction selection, signedness, width and truncation.
4. Register allocation and variable lifetimes.
5. Placement, literal pools, alignment and branch/relocation encodings.

If only a few instruction-order differences remain after structure is aligned,
trace the frozen preprocessed input through the compiler's existing RTL dumps
before trying more source permutations. Identify the first pass where the order
appears and inspect the actual compiler pass list; do not assume a generic
scheduler exists. Source expansion can depend on whether a callback value or
field address is an explicit named intermediate before the next expression.
Test the source-backed constraints separately, then combine independently
verified fixes and run the relevant behavior bank. Record diagnostic compiler
cost and retained snapshots; no new tracing framework is required.

Freeze source, headers, toolchain and the case bank before an experiment. Use
the [structural diagnosis procedure](asm-to-c-migration.md#diagnose-structural-differences-before-chasing-exact-bytes).
Keep fixed O2 and the pinned CPU/ABI/interworking settings. Diagnose source
fidelity with the owning actor; no per-method flag search or historical rebuild.

The worker can evaluate a small declared set of independent hypotheses with one
local comparison table and promote the best supported candidate. Each hypothesis
changes one cause and records cost and rejected results. Three rejected
hypotheses with the same structural obstruction trigger implementer diagnosis
within the owning actor; preserve the draft, clocks and acceptance scope.
Use the bounded3/6-cause rules below without a silent budget reset.

Bound a work packet by source hypotheses and effort, rather than one command.
Routine syntax, input-path and pinned-compiler compatibility repairs remain
authorized within the same hypothesis. Preserve and charge every failure, keep
the validators, and continue through a meaningful compile/behavior decision.
An unsupported offset-assertion spelling does not invalidate a layout hypothesis.
Three identical technical failures require diagnosis; do not create a routine
administrator-approval stop after each compilation.

### Correctness repairs before matching trials

An identified ABI, object-width or argument-count error is a correctness repair,
not another spelling hypothesis. Before the first source-order/allocation trial,
reconcile the original method's complete call-site argument/return map with the
reused helper contracts and candidate declarations, including stack arguments.
An original register setup is evidence to interpret with the callee contract,
not an automatic parameter count. A known wrong call invalidates the matching
baseline: stop tuning its prologue, correct the proved contract in the owned
source, then compare the method again. Preserve and charge all invalid attempts;
do not reset the method clock or the matching budget. The owner may make the
concrete repair within its active scope without routine approval. A frozen task
needs an explicit owned repair packet so two lanes do not reopen it. Unresolved
ABI uncertainty still requires diagnosis; this rule grants no blind extra trials.

Validate a representative before applying a reusable rule to related methods.
Structural similarity or relocation-normalized agreement is diagnostic. Exact
matching requires full pinned-byte equality at the declared original mapping;
never replace readable C with opaque ASM to meet the measure.

## Execute and reuse evidence

Compile only the changed method/module using the existing local compiler entry
points. Inspect size, entry validation, difference records and strict preflight.
An unchanged global index and full-ROM rebuild are not iteration prerequisites.
An unsupported layout remains an explicit failure, never a disabled validator.

The worker validates fixture expectations against retail before freezing them.
For nonexact semantic acceptance of a changed binary, run the relevant independent
bank. Full native exact uses the mechanical path above. If
the binary and all relevant dependencies are unchanged, execute only changed
inputs and reuse exact previous results. Record identities for source, headers,
binary, cases, oracle, helper contracts and runner; a new path or unrelated HEAD
does not alone invalidate a result. Independent wrong-return/write/order/ABI
controls remain required where relevant.

After context recovery, read the current assignment, round artifacts, accepted
case identities and unresolved failures before choosing an action. Reconcile
disk evidence against the summary. Do not rerun an accepted bank merely because
the conversation summary omitted it, or rerun tests to obtain missing timing.
Unknown timing remains unknown.

Integrate a coherent accepted batch through the production builder separately.
Report local acceptance, exact matching, actual-image integration and natural or
hardware validation independently. Retained retail suffixes and controlled
helper fixtures remain explicit limitations.

## Required measurements

| Measure | Definition |
| --- | --- |
| Candidate C | Unique current compiled C span; unfinished work, not accepted delivery |
| Accepted C | Newly complete methods passing their declared local ABI/behavior gates |
| Exact matched C | Newly complete accepted C methods with exact reference equality |
| Integrated C | Accepted C selected and verified in the production image |
| Original span | Unique original method envelope represented at each gate |
| Iteration latency | Previous decision timestamp to next decision, including gaps and failures |
| Handoff latency | Frozen dependency ready timestamp to consumer start timestamp |
| First-pass acceptance | Methods passing a gate on their first actual attempt / attempted methods |

Report generated C spans and represented original spans separately, with retained
retail bytes, veneers, literals and alignment identified. Generated spans may
contain compiler tables/literals and are not an instruction-byte count. Never
credit declarations, reused dependencies, repeated builds or scattered equal
bytes as newly exact-matched whole functions. Keep rollback/correction records
so cumulative retained totals and the current inventory reconcile.

For each gate, throughput is unique newly delivered bytes divided by elapsed
wall-clock hours. Count a method once at each gate. Report cumulative task rates
and deliveries in the trailing sixty minutes. Keep cumulative time running
through preparation, failed attempts, administrator experiments, recovery and
handoff gaps. A last-success timestamp cannot stand in for the current report
time. Parallel actors' effort is diagnostic; do not sum it into wall time.

At every decision, retain start/end, candidate and dependency identities, actual
command timings, phase effort, compile attempts, executed/reused case IDs,
failure cause, acceptance scope and the next action. Report mean, median and
nearest-rank p90 decision cycles, sample count and missing intervals. Command
timings are nested components, not additional elapsed time. Unknown intervals
are neither proven idle nor compiler time. Initial analysis is reported
separately and remains included in cumulative delivery time.

Record a compact outcome and timestamp immediately after each candidate result,
including failed compilation and byte-identical variants; do not wait for final
method acceptance to create intermediate decision records. Separate context
compaction, recovery reads, dependency waiting and commands when their actual
events are available. Use interval unions for overlapping command durations.
Leave any remaining wall time unclassified instead of attributing it to idle,
reasoning or compilation. Keep read output bounded to the active evidence so
repeated large report dumps do not increase context and recovery overhead.

## Evaluate the workflow

Evaluate the next three complete related core methods, including preparation,
validation, failed experiments and administrator overhead. Compare equivalent
complexity and contract readiness; a tiny helper versus a large controller is
not a speedup comparison. With a zero matched baseline, report new matched
bytes and elapsed time rather than an undefined improvement ratio.

Initial scheduling targets are decision-cycle median at most sixty seconds,
p90 at most 180 seconds, and handoff within sixty seconds while the administrator
is executing. These are provisional targets, not achieved results or reasons to
skip checks. Use complete method time and accepted/matched bytes/hour to decide
whether a change repays its implementation cost.

Administrator reports must name the delivered workflow change, actual cost,
resolved blocker and demonstrated saving or unmeasured result. Documentation,
case count, compiler speed or faster later rounds alone cannot establish improved
delivery. Start new tooling only for a measured repeated critical-path cost with
a bounded intervention and equivalent-work acceptance.
# Successful rewrites feed the next method

Record each matching decision and submit the evidence-bearing local gate as
soon as its required checks pass. Submit before lesson/naming paperwork or any
hourly summary; preserve distinct local, independent and integrated gates.
Quiet execution suppresses chat, not per-function progress delivery.

Follow [the reusable lesson protocol](c-recovery-lessons.md) after every
successful semantic rewrite or local whole-function match. The implementer
updates its owned method lesson, including acceptance limits, source/ASM feature,
responsible compiler pass, full elapsed time and the next testable application,
before taking the next method. Existing matching lessons are an input to the
next source map. Do not claim acceleration until comparable delivery measures
show it. Keep main and worker lesson paths disjoint; this adds no administrator
C-review gate.

## Keep difficult matching experiments bounded

At each candidate decision, state the first unresolved structural difference,
the one source-backed cause being changed and the predicted generated change.
Use the original source map and, when necessary, the existing RTL dump to test
that prediction. A smaller output or more scattered equal bytes alone is not a
confirmed cause. Close byte-identical spelling classes instead of retrying them.
Repeated structural failures exhaust the existing bounded hypothesis budget;
freeze the actual blocker and advance to a scoped successor.

Do not send every lane into another large, unresolved dispatch family merely
because it is next in an old priority list. Preserve active work, then use one
representative for a difficult family and keep other lanes on disjoint bounded
core transactions. Establish responsibility, ABI and independent obligations
before coding; smaller size alone does not establish readiness or justify helper
quota work. Promote a source rule only after the representative supports it.
Measure task mix, complete wall time and gate output before claiming improvement. Include started-cohort size/CFG strata and unfinished counts in that comparison: faster decision intervals can coexist with lower exact output when many lanes enter large unresolved controllers. At the next task boundary, preserve core priority but prefer demonstrated shared-record/ABI readiness; keep one bounded representative for an unproven large family before distributing that family. Do not infer a universal small-function advantage, split complete methods, or restart active work merely to improve the metric.


## Complete exact C delivery

For a complete original function with source/header/toolchain-bound build evidence, pinned retail revision and byte-for-byte identity across its full original instructions, literals, jump tables and alignment at the original entry/placement, use mechanical provenance and full-range verification instead of duplicate human C semantic review or rerunning unchanged behavior banks. Confirm production-linked bytes before integration. A partial prefix, retained original instructions, relocation, changed source without provenance or uncertain boundaries does not qualify; independent source/behavior acceptance remains required for nonexact work. The legacy ledger peer_exact gate may record an actual independent mechanical verification, explicitly labeled whole_exact_mechanical in its receipt; it must not imply a human source review. Prior manual review quotas do not block complete exact delivery. Preserve historical gates and use coherent batch integration with unsigned explicit-path commits.

If the independent mechanical verifier finds **tool-only provenance drift**, it may perform one current fixed-O2 method build from the unchanged frozen inputs in a fresh owned output directory. Verify the frozen source, headers, configuration, original range and binary pins first. Preserve the old report and original method clock. Record the refreshed gate only when current native provenance and strict full-range checks pass and the output equals both the pinned retail range and the previously credited binary. Source/configuration/ABI/range drift, missing required pins, changed output or a failed check stops that packet for an explicit repair; do not silently edit source or reset a matching budget. No full-ROM build or unchanged behavior-bank rerun is needed for this tool-only refresh. Keep refresh seconds separate from handoff delay, and never count these bytes as newly generated C. This bounded action is part of existing verifier ownership, so it does not require another administrator dispatch.

For exact-directed work, write the original-source ABI, linkage, object/CFG and width/snapshot map before coding, then compare the complete compiled span before creating new emulator fixtures. Do not prepare a new bank or negative mutant for every nonexact matching draft. Exact success follows mechanical provenance/full-range checks; an exhausted nonexact cause freezes without semantic credit. Tasks explicitly delivering nonexact semantic C retain independent behavior validation.

## Conditional matching budget

After three unsuccessful effective source hypotheses, stop editing and reconcile the failed causes before using any extension. A best full-original-range matching ratio strictly above 70% permits at most three additional evidence-backed hypotheses, not three automatic retries. Near-exact candidates must first complete the whole-method diagnosis below. At or below70%, retain the ordinary three-trial bound; a terminal method needs a supported explicit continuation. Setup repairs and binary-identical spelling retries remain charged but are not new useful hypotheses. Six unsuccessful effective trials freeze the best candidate and all failed classes for a supported diagnosis or independent continuation; this does not automatically change a model or reset a budget. Keep current model settings unless the user changes them. Only complete original-range identity creates exact delivery credit.

### Near-exact plateau: whole-method diagnosis before another edit

Use this checkpoint when three source hypotheses have failed to close a method
and the best pinned comparison either matches at least 95% of the complete
original span or leaves at most 16 unmatched original bytes. Roughly ten bytes
remaining is a diagnosis trigger, not proof that the cause is local. Report
generated/original lengths, missing and extra bytes separately: a short matching
prefix or a length difference never establishes a whole-function match.

The current implementation owner performs the following diagnosis. A terminal
method can continue only through a supported bounded packet and exclusive atomic
claim, preserving prior hypotheses and clocks. Administrator measures priority
and cost; it does not assign methods, review candidate C or grant acceptance.

1. Freeze the best source/header/config/toolchain/binary/report identities and
   retain the original start time. Reconcile all actual attempts, identical
   binaries and closed hypotheses before another command. Do not rebuild merely
   to refresh unchanged evidence.
2. Reread the **complete original ASM, complete candidate C and generated ASM**,
   including callees' existing contracts, shared tails, literals and alignment.
   Map arguments, every basic block/edge, object access widths, evaluation order,
   cross-call reloads and live ranges through entry and exit. Check whether a
   distant declaration, initialization, join or loop update explains both an
   early and a late mismatch; do not only inspect the remaining byte offsets.
3. Classify every residual difference as an instruction/dataflow difference,
   register allocation or lifetime, ordering/CFG, literal/relocation, or layout.
   Distinguish the first causal divergence from downstream encoding changes.
   Compare semantic operations as well as raw offsets; diagnostic alignment does
   not replace exact byte comparison or permit adjusting the original span.
4. Write a short causal conclusion: original evidence, candidate difference,
   rejected explanations, and one falsifiable next change with predicted effects
   on **all** affected sites. If multiple causes remain indistinguishable, inspect
   existing RTL/pass evidence first; use one unchanged-input diagnostic only when
   needed to separate them. Do not require RTL when source evidence is sufficient.
5. Only then use the remaining authorized trials, changing one cause per trial.
   Reconcile the prediction after each result; a score increase alone is not an
   explanation. No new supported cause means freeze and hand off, not more casts,
   variable permutations, flag changes or a ground-up rewrite. A review does not
   reset the six-trial budget. A new owner needs an explicit bounded extension and
   consumes the original failed classes and clock.

Attach this checkpoint to the existing method evidence and ledger progress:
`trigger | best report and hashes | whole-method map | residual cause table |
closed hypotheses | next prediction or blocker | review start/end | trials left`.
Record review time, subsequent attempts, exact result and complete elapsed time.
Track how many near-exact diagnoses reach whole exact and their time to closure;
do not claim a speedup from a smaller residual alone. Keep the receipt concise;
one diagnosis per unchanged plateau is enough.

## Completed mixed migration and priority

Complete byte-identical mixed code with less than10% inline assembly instruction
bytes counts in completed original-ASM migration. Keep pure-C and mixed totals
separate; a mixed function is not pure C. Divide inline instruction bytes by all
generated instruction bytes, excluding literal data, alignment and veneers.
Low-level engine, graphics and audio may carry higher explicitly documented
ratios; this allowance does not raise their priority above gameplay decisions,
mission advancement or inventory/economy/persistence. Do not infer a low-level
exception from a name or caller. Preserve complete range/provenance gates and
readable surrounding C. After near-exact diagnosis, an owner may select a bounded
explained island within its active scope; do not reopen every frozen method.

Before choosing a bounded instruction island, map the complete original operation
and its live inputs, outputs, scratch registers and memory effects. A matching
local sequence does not guarantee the surrounding allocation: opaque outputs can
change later value-range lowering, and a high-register output can add shared
save/restore instructions. Reject a transfer whose remaining differences require
absorbing control flow or literal pools. Name a compiler pass only when existing
pass evidence establishes it; otherwise label the mechanism as observed output
or a hypothesis. Completed A6F20/26AB8/13233C/C1B8C/A89D8/CEA80/43DF4 boundaries
illustrate distinct constraints, not one reusable register recipe.

Reuse a known supported mixed manifest/build route and pinned Thumb helper
aliases before the bounded compilation; a pure-C-only selector cannot accept a
mixed result. Keep metadata, mnemonic and link repairs separate from source
hypotheses, preserve failed commands, and count actual compiler invocations.
When a captured unchanged object permits a link-only repair, preserve its native
input hashes and validate the corrected ELF entry, sections and complete retail
span without claiming another C compilation. Keep exact decision, local gate and
frozen publication times separate; these steps do not relax provenance, inline
ratio or production identity gates.

## Generated ROM retention

Use the configured external data root for private evidence and ROM outputs. Before producing another full image, clean obsolete images owned by the same lane using the local assignment retention command. Retain original reference ROMs, saves, current build/replay inputs, frozen images still needed for acceptance, and the latest required integrated baseline. Record deleted image hashes and sizes; preserve source, manifests, reports, small method binaries and original clocks. Hourly cleanup is a bounded tool operation, not an LLM task. For unchanged large frozen JSON snapshots on APFS, prefer native copy-on-write clones over reading and rewriting the entire document; each snapshot keeps an independent inode and identical bytes. Never hard-link potentially writable evidence or rewrite pinned JSON just to move storage.
