# Using the GBA resource collection during recovery

This adapts the supplied general-purpose workflow to this repository. Start at
the [resource index](gba-asm-to-c-resources.md); repository AGENTS.md, the local
assignment and the workflow CLI remain authoritative. Reading or installing all
resources is never a prerequisite for the next dependency-ready method.

## One bounded method

1. **Resume the existing owner and history.** Use the actual ledger claim,
   original method clock, source inventory and failed hypotheses. Self-claim a
   disjoint method in the active battle group; finish current work first.
2. **Pin the original target.** Reuse the verified US retail revision, full
   native range/mode and source-hash-bound inventories. Distinguish instructions,
   literal pools, tables, alignment and assets. No whole-ROM redisassembly.
3. **Assemble a sufficient context.** Establish arguments/returns, stack/frame,
   physical objects and effects from original ASM and callers. Reuse simple
   completed dependencies and typed interfaces to complex low-level bodies.
4. **Retrieve the closest useful successful family.** Consult frozen FFTA
   lessons first, then the selected external reference. Verify constants,
   widths, branch targets and owner-specific differences rather than copying a
   normalized sibling wholesale.
5. **Recover readable source.** Preserve definitions, operand widths, CFG joins,
   calls, snapshots/reloads and narrowing. Ghidra or m2c output is an optional
   draft, not the original source or proof of a complete boundary/ABI.
6. **Compile locally with the existing fixed O2 pipeline.** Use method/module
   builds and pinned provenance. Classify the first mismatch as operation/type,
   CFG, lifetime/allocation/reload or placement before the next one-cause edit.
   Apply the existing plateau checkpoint and cause budget.
7. **Submit the actual gate immediately.** A full native exact match uses the
   existing mechanical provenance/range gate; nonexact semantic work still needs
   its independent source-derived checks. A diff score or emulator agreement is
   not interchangeable with complete byte identity.
8. **Capture the transferable result and continue.** Record the successful or
   failed rule, counterexample and full elapsed cost in the method lesson. Main
   integrates coherent batches while independent source work continues.

## Choose the smallest useful reference

| Actual unresolved question | Consult | Avoid |
| --- | --- | --- |
| Instruction/mode, sign, PC or BIOS semantics | [ISA lookup](gba-asm-to-c-idioms.md), ARM manual, GBATEK, Tonc | Decoding ARMv5/Thumb-2 or literal data as ARMv4T instructions |
| IO width, SWI or register name | `vendor/libgba/include`, `vendor/libtonc/include` | Replacing a historical helper with a modern SDK or ABI implementation |
| Missing draft/type context | `vendor/m2c/README.md`, Ghidra ARM processor reference | Treating a decompiler's inferred local/prototype as established evidence |
| Source-family shape and state ownership | [pokeemerald study](pokeemerald-reconstruction-reference.md), Klonoa learnings | Assuming Pokemon or another game's types/flags/layouts are FFTA's |
| Near-match register or reload plateau | [EDS study](eds-matching-reference.md), existing RTL artifacts | Reordering every later statement when an earlier reload is the cause |
| A repeatedly expensive local diff/search | `vendor/asm-differ`, `vendor/objdiff`, `vendor/decomp-permuter-agbcc` | Starting a second build/provenance pipeline or unbounded permutation jobs |
| Behavior of a genuinely nonexact entry | Existing mGBA executor and independent bank | Installing another emulator or rerunning unchanged cases without a reason |

For optional m2c use, its README documents the `gba` APCS target, GCC source
target and context files. Supply the current method's actual prototypes,
objects and symbols; keep generated drafts/caches in owned build/evidence paths.
The reference checkout alone does not install its dependencies or prove tool
compatibility. No tool installation or reference-project build is required here.

## Adaptations to the supplied workflow

- Its compiler fingerprint matrix is a general research technique, not a new
  FFTA iteration step. Our established fixed O2 profile is unchanged. A genuine
  compiler-boundary question needs separate concrete evidence and authorization.
- Its Ghidra/loader and Luvdis steps are optional targeted cross-checks, not a
  mandatory import or rescan of the whole game. Reuse existing entry/index proof.
- Its knowledge-base preparation is incremental at a real dependency, not an
  up-front rewrite of every SDK/interface or global header.
- A documented register binding or instruction-free empty ASM constraint may
  solve a concrete allocation/lifetime requirement. Accurate readable logic,
  valid operands and full native identity remain necessary. Reference projects'
  conflicting opinions about source authenticity do not override this rule.
- Public scratch services and autonomous orchestration tools are references;
  this collection does not authorize uploading private targets or starting
  external services. Existing claims and publication ownership remain intact.
- Functional FFTA reimplementations and host static recompilers may supply
  research hypotheses. Their native-host output is not recovered GBA C credit.

## Measure a useful change

Use existing round and gate records, not another mandatory form. Record which
reference resolved which uncertainty, compiles/failed hypotheses to the next
decision and complete elapsed time. Compare adjacent complete absolute hours
using matched original ASM envelope B/h, with local, independent and integrated
gates separate. Cloning projects, collecting links and producing drafts create
no matched-byte credit or demonstrated speedup.
