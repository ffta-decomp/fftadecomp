# Upstream imports and provenance

Recovered implementations imported from [shubshub/fftadecomp](https://github.com/shubshub/fftadecomp) are identified in each source header, the completed-source index, and [JSON](../data/upstream-imports.json)/[CSV](../data/upstream-imports.csv) progress records. The latest cohort is pinned to PR #18 commit `ece7856b4816550174d46a7e6e9b246a5a70a54c`; earlier locally adapted imports retain their original commit attribution. Existing notices remain; no additional license grant or authorship transfer is implied.

Import is not independent rewriting. Every accepted new source is compiled locally with the pinned compiler and original O2/interworking profile. The full ELF function span, entry and complete generated bytes are checked against the private US reference. Only outside-function terminal alignment can be excluded; instructions are never copied from the reference to repair a candidate. The final completed-source build checks all modules and whole-image equality.

Overlaps with previously published completed spans are skipped, so the new cohort adds distinct original bytes. Failed candidates and inline-assembly candidates awaiting a separate mixed audit are not counted or published as completed. Source comments carry attribution; address-only linker aliases adapt symbol names without importing ROM payloads. No story/dialogue text, translation packs or ROM is included.

The import progress files describe the reproducible public completed-source build. Daily charts use the existing native ledger and its fixed catalogue, so these are separate scopes: do not add the two totals or infer new independent peer receipts, historical hourly throughput or private production integration. The `origin=upstream_import` marker remains attached when these spans are reconciled into other views.
