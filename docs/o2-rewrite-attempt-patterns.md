## A smaller decision before each compile

Write one sentence with these fields in the existing source map or ledger
record, rather than creating another report:

`original operation -> source object/value boundary -> predicted emitted change
-> relevant behavioral obligations -> condition that rejects the hypothesis`.

Classify the first difference before choosing the next action:

1. Wrong physical object, offset, width, helper argument or reload: resolve the
   original-source contract before matching. A passing narrow bank is insufficient.
2. Wrong promotion/truncation already in initial RTL: reconstruct the actual
   operand definitions, not merely the result type.
3. Constant expression changes during CSE: distinguish an integer address from
   a verified linker-bound object. Do not add an accessor by habit.
4. Index becomes a second cursor in `.loop`: examine induction width, stride,
   bound and live uses. A spelling that already collapsed is not a new cause.
5. Structure survives until allocation: examine actual simultaneous lifetimes
   and calls. Renaming/declaration order is not a register contract.

Use final ASM first. A clearly localized source-backed change can need only one
compile; an unknown transformation needs a bounded diagnostic. There is no
requirement to dump every method or rerun a diagnostic for the same frozen input.

## Keep setup errors separate from source failures

Before the first candidate, reuse proven target-compatible size/offset
assertions and the existing executor interpreter/adapter command. The effect-91
modern-offset builtin failure and effect-92 missing-Unicorn negative-control
command were avoidable setup failures. Preserve and charge them; never remove
layout checks or an oracle to make a command pass.

Two successful worker methods illustrate the cost boundary: effect 28's eight
local build-wrapper calls totaled 9.935 s against 1,389.735 s to its local
evidence; effect 43's five totaled 7.811 s against 1,220.411 s to publication.
These measured command totals are below 1% of those gross cycles. They do not
classify the remaining time as idle, but do not justify another compiler-speed
project. Reuse compatible fixture/ABI/environment metadata and proven source
forms instead. Record binary hashes directly from files or reports: recent
manual hash corrections were bookkeeping failures, not changed candidates.

Check three separate sizes: original complete envelope, current selected C
prefix, and generated candidate. A prefix can be shorter because an earlier
semantic migration retained original suffix bytes. An envelope correction is
a private partition/preflight question; it must not silently change production
or count retained bytes as recovered C. Fitting that original envelope still
does not establish exactness or independent acceptance.

One changed fitting binary executes its relevant independent cases. An unchanged
binary reuses precisely identified compatible evidence. Freeze a bounded
failure, release the claim and take a ready successor; keep the original gross
clock if a later supported cause reopens the method. Every successful transfer
updates its actor-owned lesson, including the counterexample and actual gate.

It is not a universal struct rule or measured global speedup.

For an exact-directed method, establish original ABI/linkage, layouts, CFG and width/snapshot obligations, then compare the local compiled complete span before building new emulator fixtures. Complete exact output follows mechanical provenance/range verification; do not create duplicate runtime banks or human source reviews. A bounded nonexact matching attempt freezes and advances without claiming semantic acceptance. Nonexact semantic-delivery tasks retain their independent behavior gates. Materialize values at their original definition points; declaration permutations and binary-identical casts do not constitute new causes.
