# Mission controllers: select source forms from value uses

The source95 cohort admitted ten complete core methods, 4,158 original bytes.
Seven reached local whole-function exact C, 1,836 original bytes. Preparation
through the last method freeze took 1,473.540407 seconds across concurrent lanes,
or 4,485.52 locally matched original bytes/hour for this finite cohort. This
includes preparation, unsuccessful methods and handoff time. It is not a
trailing-hour rate, independent acceptance rate, integration rate or controlled
speedup measurement. Two of ten first recorded attempts were exact; setup
failures remain in the record.

All five registered scene controllers in that cohort matched: 9C18, 5CF5C,
5D534, 5D784 and 5F2A8, totaling 1,648 bytes. The other two successes were A06C
and 360F8, 188 bytes. The 447B4, 4409C and 44158 attempts remain nonexact and
contribute zero matched bytes. This small selected cohort supports preparing
related core controllers together; it does not establish that all controllers,
small methods or nearby functions are easier.

## Three decisions before the first source

1. **Recover result groups from actual branch destinations.** In
   [5D534](../main/grouped-mission-status-cases.md), the original has result
   groups 1/2 and 3/4 with different effects. A nested switch closed the final
   two bytes of a 590/592-byte candidate without adjusting constants or flags.
   A numeric interval with unrelated threshold semantics is a counterexample.
2. **Separate object width from the value's promoted use.** In
   [5D784](../worker3/SceneRegisteredRoot_0005D784.md), the phase is physically
   a byte, but its captured value feeds signed dispatch and survives calls into
   different argument widths. u8 produced an extra copy and 412 bytes; u32
   removed the copy but changed the comparison tree and produced 404 bytes.
   A signed promoted local reproduced all 408 bytes. Keep the field byte-sized
   and preserve helper prototypes; this is not permission to widen every local.
3. **Mark captures and reloads at each call boundary.** The first-source
   136-byte 5F2A8 result controller preserved an entry snapshot for one store,
   then reloaded the live root after reset/start/close helpers. The successor
   [5E798](../main/mission-cancellation-operation-refresh.md) independently
   reproduced all 204 bytes on its first source in 82.253221 seconds from claim
   to local decision. Its operation-array pointer survives the resolver and
   enumerator, while the returned count uses a fresh context. These distinct
   definitions matter more than naming every pointer identically.

The lessons describe observed generated output. No responsible internal compiler
pass was traced for these three cases. The 204-byte successor is outside the
source95 count and rate; it provides another site-specific capture/reload
example, not a measured saving against a control implementation.

## Avoid preparation mistakes without adding another gate

Resolve actual helper exports and verify physical object offsets before the
first build using existing local tools. Do not opt into a dead-switch-pointer
exception merely because the C contains a switch: 5D534 first failed that
metadata guard when the emitted object contained no such data. Inspect the
existing generated section result before applying a relevant exception. Keep
the failed setup cost in the original clock.

Reuse the family context and helper facts, then make one compact per-method map
of groups, widths, captures and reloads. Record the applicable original feature
and predicted emitted change in the existing round summary. No new form,
approval loop or repeated passing bank is needed. An unsupported transfer is a
reason to narrow the lesson, not to cycle declarations or optimization flags.
