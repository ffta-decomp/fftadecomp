## Original feature and prior failed hypotheses

The original loads the dispatch-slot base into r2; the selected definition's
halfword ordinal uses r3 and forms the indexed slot address through r1. Earlier
typed-symbol work restored the operation/load order but left the slot/ordinal
register roles inverted. Its best unchanged-size result was 39/44 bytes.
The frozen local-allocation diagnosis already identified that inversion.
Explicit ordinal/slot-address definitions produced the same binary; a mutable
cursor was worse. Neither equivalent declaration changes nor another optimizer
level supplied a new explanation.

## Successful source mechanism

The successful method restores the frozen typed two-table source, binds its
**initialized slot-base pointer** to r2, and consumes that value through an
instruction-free read/write ASM operand at the original base-definition point.
The ordinary lookup, narrowing, actual call and helper implementation remain.
This corrects the observed allocation requirement without an instruction island,
dummy value, compiler patch or generated padding.

A local fixed-register declaration alone is not a general allocation guarantee.
The explicit supported ASM operand is part of this measured formulation. Its
effect must be checked against the complete generated native span; do not infer
that binding an arbitrary pointer to r2 always improves a method.

## Technical failure to avoid

The first command failed because declarations followed the empty ASM statement
under the pinned C89 compiler. The second command moved declarations before
the statement while retaining assignment-before-use and the same constraint
cause, then matched. For a similar edit, declare all block locals before the
first statement/ASM. An empty output-only constraint cannot fabricate an input.

## Transfer conditions and falsifier

Use this when original and generated operations, object/ABI definitions, widths,
branches and placement already agree, and the existing pass evidence isolates a
specific allocation-role inversion. Predict the affected live value and exact
original register before the edit. A changed frame, extra move, altered load or
remaining mismatch falsifies closure; it does not justify registering the rest
of the function by hand. Earlier loop/combine differences need their own cause.

Newly permitted compiler constraints resolved this one previously frozen case.
One success does not establish a general throughput multiplier. Record actual
